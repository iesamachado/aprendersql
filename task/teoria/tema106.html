1. ¿Qué es SQL/PSM?

SQL/PSM (Persistent Stored Modules) es una extensión de SQL que nos dota de herramientas de programación procedural. Nos permite crear bucles, condicionales y variables directamente dentro de la base de datos (MariaDB / MySQL).

Lo que SÍ permite
  • Tipos de datos y Variables locales.
  • Estructuras de control de flujo (IF, CASE, WHILE).
  • Programar Funciones, Procedimientos y Triggers (disparadores).
Lo que NO permite
  • No permite crear interfaces de usuario (ventanas, botones).
  • No crea aplicaciones ejecutables (como un .exe o .apk), son scripts que viven en el servidor de datos.
¿Es lo mismo que PL/SQL o T-SQL? No. PL/SQL es el lenguaje de Oracle y T-SQL es el de SQL Server (Microsoft). Se parecen mucho, pero SQL/PSM es el estándar que usa MariaDB y MySQL.

2. Funciones sobre Cadenas (Varchars)

Antes de programar, debemos dominar las funciones predefinidas de SQL para tratar textos:

FunciónDescripciónEjemplo
REPLACE(cad, buscar, nuevo)Cambia un trozo de texto por otro.REPLACE('Hola', 'a', 'o') -> 'Holo'
LEFT(cad, num) / RIGHT()Recorta la cadena por la izquierda o derecha.LEFT('Murcielago', 3) -> 'Mur'
TRIM() / LTRIM() / RTRIM()Quita espacios en blanco de los extremos.TRIM(' Hola ') -> 'Hola'
LENGTH(cad)Devuelve el número de caracteres (longitud).LENGTH('Hola') -> 4
CONCAT(cad1, cad2...)Une varias cadenas en una sola.CONCAT('A', 'B') -> 'AB'

3. Bloques de Código y Variables

Bloques BEGIN...END

En SQL/PSM, los bloques de código se encierran entre BEGIN y END. Es el equivalente a las llaves { } en Java o C++.

Declaración y Asignación de Variables

Las variables son volátiles (se destruyen al terminar el script). Se declaran con DECLARE y se asignan con SET o dentro de un SELECT.

BEGIN
    -- 1. Declarar (Nombre y Tipo)
    DECLARE mi_fecha DATE;
    DECLARE contador INT;
    
    -- 2. Asignar valor (Setear)
    SET mi_fecha = NOW();
    
    -- También se puede setear el resultado de una consulta (si devuelve 1 valor)
    SET contador = (SELECT COUNT(*) FROM clientes);
END;

4. Estructuras de Control

Condicionales (IF ELSE)

A diferencia del CASE WHEN que va dentro de una consulta, el IF define bloques lógicos de código en procedimientos.

IF num > 150 THEN
    SELECT 'Ya tengo todos los pokemons';
ELSE
    SELECT 'Aún tengo que insertar más';
END IF;
Bucles (WHILE)

Itera mientras se cumpla la condición. Muy útil para recorrer registros o cálculos matemáticos recurrentes.

WHILE num > 0 DO
    SET resultado = resultado * num;
    SET num = num - 1;
END WHILE;

5. Procedimientos Almacenados (Procedures)

Un procedimiento es un script guardado en la base de datos con un nombre. Se pueden llamar externamente y pueden modificar datos.

Sintaxis Básica y Ejecución

CREATE PROCEDURE HolaMundo()
BEGIN
    SELECT 'Hola Mundo!';
END;

-- Para ejecutarlo usamos CALL:
CALL HolaMundo();

Parámetros de Entrada (IN) y Salida (OUT)

Los procedimientos pueden recibir variables de entrada para filtrar datos, y devolver múltiples variables de salida.

-- Parámetros de Entrada (IN)
CREATE PROCEDURE plantilla(idEquipo INT, pais VARCHAR(20))
BEGIN
    SELECT nombre FROM jugadores
    WHERE equipo_id = idEquipo AND nacionalidad = pais;
END;

CALL plantilla(1, 'Spain');
-- Parámetros de Salida (OUT)
CREATE PROCEDURE contarJugadores(OUT total INT)
BEGIN
    SET total = (SELECT COUNT(*) FROM jugadores);
END;

CALL contarJugadores(@conteo);
SELECT @conteo; -- Ver el resultado

6. Funciones Personalizadas

A diferencia de los procedimientos, una función SIEMPRE devuelve un valor, y se puede usar en medio de cualquier consulta SQL habitual (como un SELECT o UPDATE).

CREATE FUNCTION celsiusToFahrenheit(celsius REAL) 
RETURNS REAL
BEGIN
    RETURN celsius * 1.8 + 32;
END;

-- Se ejecuta como cualquier función nativa de SQL
SELECT celsiusToFahrenheit(25) AS temp_madrid;

7. Procedures vs Funciones

PROCEDURES
  • Tienen que llamarse con CALL nombre();
  • Pueden tener Múltiples variables de salida (OUT).
  • Sí pueden ejecutar modificaciones en las tablas (INSERT, UPDATE, DELETE).
  • Pueden contener/llamar a otros procedures y funciones.
FUNCIONES
  • Se llaman dentro de consultas: SELECT mi_funcion();
  • Solo pueden tener Un solo RETURN de salida.
  • No pueden modificar tablas, son de solo lectura.
  • No pueden contener ni llamar a un procedure.
