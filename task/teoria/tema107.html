Restricciones Semánticas y Dominio

Texto / Cadena

Fecha / Booleano
Tipos de Claves
  • Superclave: Posible conjunto de atributos que identifican un elemento.
  • Clave Candidata: Mínima superclave posible.
  • Clave Primaria (PK): Clave candidata escogida por el diseñador.
  • Clave Foránea (FK): Atributo relacionado con otra entidad. Debe existir como PK en la otra.
Otras Restricciones
  • Valor Único (Unique): No puede repetirse, pero no es PK.
  • Nulo (Null / Not Null): Atributos que pueden dejarse vacíos o no.
  • Integridad referencial: Validar que las FK apuntan a PK existentes.

Transformando de E-R a Lógico

Concepto E-R Transformación Lógica
Entidad Se convierte en una Tabla. Atributos -> Columnas. PK -> Primary Key.
Relación 1:N Se crea una Clave Foránea (FK) en el lado de la N que apunta al 1.
Relación N:N Se crea una Tabla Intermedia con las FK de ambas entidades como su PK compuesta.
Relación 1:1 Pasar los atributos a una sola tabla o mantener dos tablas con FK (única).
1:N Reflexiva Se crea una FK a la misma tabla.
Superclases 1) Crear tabla para super y subclases (con FK).
2) Bajar todo a las subclases.
3) Subir todo a la superclase con un campo "tipo".
Reglas del Diagrama de Tablas: Toda tabla tiene 1 sola PK. Nombres no se repiten. Las FK deben estar indicadas explícitamente. Las relaciones se hacen entre CAMPOS, no tablas. Todo atributo debe tener dominio y marca de nulabilidad (NOT NULL).

Ejemplo 2: Relación N:M con atributos
Relación N:M: Cuando dos entidades se relacionan de muchos a muchos, se genera siempre una tabla intermedia. La PK de esta nueva tabla suele ser la combinación de las PKs de las tablas originales (PK compuesta). Si la relación en el modelo E-R tenía atributos propios, estos bajan directamente como columnas a esta nueva tabla intermedia.
Ejemplo 3: BD de una Tienda Estándar (Libros)

Este es el clásico esquema de una tienda online bien diseñada. Los productos (libros) se relacionan con los pedidos mediante una tabla N:M (DetallePedido). Fíjate en la gestión de los precios, que es crucial:

  • Precio en tabla Libros: Es el precio base de catálogo. Es el precio al que se vende el libro a día de hoy.
  • Precio en tabla DetallePedido (N:M): Es vital almacenar el precio aquí. Representa el precio al que se vendió ese libro el día en cuestión. Si el precio del catálogo sube mañana, las facturas pasadas no deben alterarse. Además, aquí se guarda la cantidad de ejemplares comprados.
  • Precio (Total) en tabla Pedidos: Es el total final calculado y pagado por el cliente en ese pedido.

Fechas y Categorización: Un buen diseño incluye un DATETIME en el pedido para guardar el momento exacto (fecha y hora) de la compra. Además, los productos se pueden categorizar: si un libro pertenece a un solo género (o editorial) será una 1:N, pero si puede tener varias categorías a la vez, requeriría una N:M.

Normalización

Es obligar a los atributos a cumplir ciertas formas normales para mejorar la calidad del diseño.

1ª Forma Normal (1FN)
No hay grupos repetitivos
  1. No hay orden arriba/abajo ni derecha/izquierda.
  2. No hay filas duplicadas (debe haber PK).
  3. Cada casilla tiene un solo valor (atómico).
  4. Columnas regulares (mismo dominio).
2ª Forma Normal (2FN)
Dependencia completa

Debe cumplir 1FN. Si hay PK compuesta, todos los atributos deben depender de la PK completa, no solo de una parte de ella.

3ª Forma Normal (3FN)
Sin dependencias transitivas

Debe cumplir 2FN. Un atributo no puede deducirse de otro atributo que no sea clave.
