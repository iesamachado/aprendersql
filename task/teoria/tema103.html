Tema 3: Modelo físico, DDL

De los 3 modelos para crear BBDD (Conceptual, Lógico, Físico), nos centraremos en el Físico (DDL).

¿Qué es DDL?

Es la parte de SQL que nos crea, modifica y borra las tablas y las relaciones de nuestra BBDD.

Serán esas instrucciones SQL para manipular la estructura de nuestras tablas. No es un diagrama como el Modelo ER o el Modelo lógico. Se escribe en texto plano.

Entorno: MariaDB

Vamos a usar este SGBD en clase. Levantaremos el motor de la BD con Docker y usaremos DBeaver para lanzar nuestras instrucciones SQL contra el servidor.

1. DDL: Definición de Datos

1.1 Creación de Base de Datos y Tablas

El DDL (Data Definition Language) nos permite crear la estructura donde se almacenarán nuestros datos. Antes de empezar a crear tablas, DEBEMOS crear una BBDD.

CREATE DATABASE nombreDeLaBBDD;
USE nombreDeLaBBDD; -- Indicamos al cliente SQL que queremos usar esa bbdd
Concepto Clave: Tipos de Datos y Restricciones

Tipos de Campo más usados:

  • INT: Para enteros (ej. IDs). Suelen usar AUTO_INCREMENT.
  • BIT: Para booleanos.
  • VARCHAR(n): Para texto variable. IMPORTANTE: Indicar la N (ej. VARCHAR(50)).
  • DATETIME: Para fechas y horas.
  • DECIMAL(18,2): Para números decimales (ej. dinero). Máx valor (18,2): 9.999.999.999.999.999,99

Restricciones disponibles:

  • NOT NULL: la columna no puede ser nula.
  • UNIQUE: el valor debe ser único.
  • PRIMARY KEY: Identificador único (implica NOT NULL y UNIQUE).
  • FOREIGN KEY: Referencia a otra tabla. Ambas columnas DEBEN TENER EL MISMO DOMINIO.
  • DEFAULT: valor predeterminado si no se especifica.
Ejemplo Completo con Claves y Relaciones
CREATE DATABASE DGT;
USE DGT;

CREATE TABLE Persona (
    dni VARCHAR(9) PRIMARY KEY,
    nombre VARCHAR(250) NOT NULL
);

CREATE TABLE Multa (
    id INT AUTO_INCREMENT PRIMARY KEY,
    precio DECIMAL(18,2) NOT NULL,
    DNI_Persona VARCHAR(9) NOT NULL,
    FOREIGN KEY (DNI_Persona) REFERENCES Persona(dni)
);

-- Ejemplo de Primary Key doble
CREATE TABLE PersonaCoche (
    DNI VARCHAR(9),
    Matricula VARCHAR(7),
    CONSTRAINT fkDNI FOREIGN KEY (DNI) REFERENCES Persona(dni),
    PRIMARY KEY (DNI, Matricula)
);

1.2 Modificación de Tablas (ALTER)

Comando ALTER TABLE. Nos permite añadir campos, eliminarlos, añadir claves foráneas, o modificar tipos de datos una vez que la tabla ya está creada.

-- Añadir nueva columna
ALTER TABLE jugador ADD email VARCHAR(150) NOT NULL DEFAULT 'asd@asd.es';

-- Modificar columna existente
ALTER TABLE jugador MODIFY COLUMN nombre VARCHAR(30);

-- Borrar columna
ALTER TABLE jugador DROP COLUMN apellido;

-- Añadir y Borrar Constraints (Restricciones)
ALTER TABLE categoria ADD CONSTRAINT pkcategoria1 PRIMARY KEY (id);
ALTER TABLE Tarjeta ADD CONSTRAINT fkcategoria FOREIGN KEY (idcategoria) REFERENCES Categorias(id);
ALTER TABLE categoria DROP CONSTRAINT pkcategoria;

1.3 Borrado (Drop)

Esta operación destruye la estructura y los datos permanentemente. ¡CUIDADO CON ESTO!

DROP TABLE NombreTabla;
DROP TABLE IF EXISTS nombreTabla;
DROP DATABASE nombreBBDD; -- BORRAMOS ABSOLUTAMENTE TODO LO QUE CONTENGA LA BBDD
¡TRUNCATE vs DROP!
TRUNCATE TABLE borra los datos pero deja la tabla vacía. DROP borra todo.

1.4 Diccionario de Datos Criterio 3.g BOJA

¿Cómo consultar el diccionario en MariaDB?

MariaDB guarda automáticamente la estructura de la BD en la base de datos del sistema information_schema. Podemos consultarla con SQL estándar:

-- Ver todas las columnas de una tabla con sus tipos y restricciones:
SELECT
    COLUMN_NAME        AS Columna,
    DATA_TYPE          AS Tipo,
    CHARACTER_MAXIMUM_LENGTH AS Tamaño,
    IS_NULLABLE        AS Permite_NULL,
    COLUMN_DEFAULT     AS Valor_Default,
    COLUMN_KEY         AS Clave,
    EXTRA              AS Extra,
    COLUMN_COMMENT     AS Descripcion
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'arepazo'
  AND TABLE_NAME   = 'Pedidos'
ORDER BY ORDINAL_POSITION;

-- Ver todas las claves foráneas de la BD:
SELECT
    TABLE_NAME     AS Tabla,
    COLUMN_NAME    AS Columna_FK,
    REFERENCED_TABLE_NAME  AS Tabla_Referenciada,
    REFERENCED_COLUMN_NAME AS Columna_Referenciada
FROM information_schema.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = 'arepazo'
  AND REFERENCED_TABLE_NAME IS NOT NULL
ORDER BY TABLE_NAME;
Comando rápido: DESCRIBE Pedidos; o SHOW CREATE TABLE Pedidos; dan una vista rápida del diccionario de una tabla concreta.
