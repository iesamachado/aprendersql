1. Introducción: La Filosofía de la Seguridad

En el ámbito de la seguridad de bases de datos, existe una regla de oro: "Ser rancios". No estamos aquí para hacer amigos; debemos ser extremadamente tacaños con los permisos que otorgamos.

Principio de Mínimo Privilegio: Si nos piden permisos para que un usuario consulte una tabla, jamás le daremos credenciales de administrador (root). Solo concederemos el acceso estricto y necesario.

2. Gestión de Usuarios y Hosts

En MariaDB y MySQL, la gestión de usuarios tiene una particularidad importante respecto a otros sistemas (como SQL Server): a cada usuario se le asocia una IP o Host desde la que tiene permitido conectarse.

  • localhost: Solo permite conexiones desde el mismo servidor donde está la base de datos.
  • %: Es un comodín que indica que el usuario puede conectarse desde cualquier máquina.

Para crear un usuario, utilizamos la instrucción CREATE USER:

-- Crear un usuario que puede conectarse desde cualquier lugar
CREATE USER 'usuario1'@'%' IDENTIFIED BY 'MiContraseñaSegura!';

-- Crear un usuario que solo puede acceder localmente
CREATE USER 'admin_local'@'localhost' IDENTIFIED BY 'SuperSecreta!';

Podemos consultar los usuarios existentes revisando la tabla del sistema:

SELECT User, Host FROM mysql.user;

3. Privilegios (GRANT y REVOKE)

Una vez creado el usuario, este no tiene permisos para hacer nada. Usamos GRANT para conceder permisos y REVOKE para quitarlos.

Asignar Privilegios

-- Dar permisos específicos sobre una base de datos entera
GRANT SELECT, INSERT, UPDATE, DELETE ON midb.* TO 'usuario1'@'%';

-- Dar TODOS los privilegios (Solo para administradores)
GRANT ALL PRIVILEGES ON midb.* TO 'admin_local'@'localhost';

Ver los Privilegios de un Usuario

SHOW GRANTS FOR 'usuario1'@'%';

Revocar Privilegios

-- Quitar el permiso de borrado
REVOKE DELETE ON midb.* FROM 'usuario1'@'%';

4. Roles (Grupos de Usuarios)

Los roles permiten agrupar permisos y asignarlos fácilmente a múltiples usuarios, simplificando la administración (por ejemplo, creando roles como cocineros, camareros o jefes).

Crear y configurar un Rol

-- 1. Crear el Rol
CREATE ROLE 'developers';

-- 2. Dar permisos al Rol
GRANT INSERT, UPDATE, DELETE ON mi_empresa.empleados TO 'developers';

-- 3. Asignar el Rol a un usuario
GRANT 'developers' TO 'usuario1'@'%';

Uso de Roles por parte del Usuario

Por defecto, los roles asignados no están activos hasta que el usuario los habilita o se configuran por defecto.

-- Activar un rol en la sesión actual
SET ROLE 'developers';

-- Activar TODOS los roles que tiene el usuario
SET ROLE ALL;

-- Configurar un rol por defecto para un usuario (requiere admin)
SET DEFAULT ROLE 'developers' FOR 'usuario1'@'%';

-- Comprobar qué rol está activo actualmente
SELECT CURRENT_ROLE();

5. Vistas (Views) como Mecanismo de Seguridad

Las vistas no solo sirven para simplificar consultas complejas, sino que son una potente herramienta de seguridad. Permiten dar acceso de lectura a datos específicos de una tabla sin revelar toda la tabla (por ejemplo, ocultando salarios o contraseñas, o mostrando nombres en lugar de claves foráneas).

-- Crear una vista segura que oculta datos sensibles
CREATE VIEW vista_menu_seguro AS 
SELECT id_plato, nombre_plato, precio 
FROM menu 
WHERE disponible = 1;

-- Dar permiso al usuario SOLO sobre la vista, no sobre la tabla original
GRANT SELECT ON restaurante.vista_menu_seguro TO 'invitado'@'%';

6. Sinónimos (Synonyms)

En MariaDB, los sinónimos (introducidos en versiones recientes) permiten crear nombres alternativos para objetos de la base de datos (tablas, vistas, secuencias).

Son útiles en seguridad para ocultar la ubicación o el nombre real de un esquema, y para facilitar accesos.

-- Crear un sinónimo para una tabla (requiere MariaDB 10.5+)
CREATE SYNONYM empleados_publico FOR hr_schema.tabla_empleados_real_2023;

-- Ahora podemos dar permisos sobre el sinónimo
GRANT SELECT ON empleados_publico TO 'usuario_reportes'@'%';
