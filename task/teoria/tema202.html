Selección de Motores: InnoDB vs MyISAM

MariaDB soporta múltiples motores de almacenamiento. Los más comunes son InnoDB y MyISAM.

InnoDB (Predeterminado)
  • Soporta transacciones (ACID).
  • Bloqueo a nivel de fila (Row-level locking).
  • Soporte para claves foráneas (Integridad referencial).
  • Recomendado para la mayoría de las aplicaciones.
MyISAM
  • No soporta transacciones.
  • Bloqueo a nivel de tabla (Table-level locking).
  • Rápido para operaciones de lectura intensiva.
  • Útil para tablas de sólo lectura o Data Warehousing.

Arranque y Parada del Servicio

Para gestionar el servicio de MariaDB en sistemas Linux basados en systemd (como Ubuntu, Debian, CentOS), se utiliza el comando systemctl.

  • Iniciar el servicio: sudo systemctl start mariadb
  • Detener el servicio: sudo systemctl stop mariadb
  • Reiniciar el servicio: sudo systemctl restart mariadb
  • Verificar el estado: sudo systemctl status mariadb
  • Habilitar inicio automático: sudo systemctl enable mariadb
Asegúrate de tener privilegios de superusuario (root o sudo) para ejecutar estos comandos.

Archivos de Log (Registro)

MariaDB genera diferentes tipos de logs que son cruciales para el monitoreo, la auditoría y la resolución de problemas.

Contiene información sobre cuándo se inició y se detuvo mysqld y también los errores críticos que ocurren mientras el servidor se está ejecutando.
Configuración típica en my.cnf: log_error = /var/log/mysql/error.log

Registra todas las consultas SQL recibidas del cliente, así como los inicios y cierres de sesión. Muy útil para depuración, pero consume mucho espacio en disco y recursos.
Configuración típica en my.cnf: general_log = 1, general_log_file = /var/log/mysql/mysql.log

Registra las consultas que tardan más tiempo en ejecutarse de lo definido en el parámetro long_query_time. Esencial para la optimización del rendimiento.
Configuración típica en my.cnf: slow_query_log = 1, slow_query_log_file = /var/log/mysql/mariadb-slow.log, long_query_time = 2.0

Parámetros de Conectividad

La configuración de red y conexión en MariaDB (generalmente en /etc/mysql/my.cnf o /etc/mysql/mariadb.conf.d/50-server.cnf) es fundamental para el rendimiento y la seguridad.

Parámetro Descripción Valor de ejemplo
bind-address Dirección IP a la que el servidor escuchará. 127.0.0.1 solo permite conexiones locales. 0.0.0.0 permite conexiones desde cualquier interfaz. bind-address = 127.0.0.1
max_connections El número máximo de conexiones simultáneas permitidas. Si se supera, los nuevos clientes recibirán el error "Too many connections". max_connections = 150
wait_timeout El número de segundos que el servidor espera actividad en una conexión no interactiva antes de cerrarla. wait_timeout = 28800 (8 horas)
interactive_timeout El número de segundos que el servidor espera actividad en una conexión interactiva antes de cerrarla. interactive_timeout = 28800

Editando my.cnf: La Configuración Real

Saber leer una tabla de parámetros está bien, pero el trabajo real de un administrador es editar el archivo de configuración y verificar que los cambios han tenido efecto. Ese archivo es my.cnf (Linux) o my.ini (Windows).

¿Dónde está mi my.cnf?
En Ubuntu/Debian: /etc/mysql/mariadb.conf.d/50-server.cnf
En Docker (montando volumen): mapear un archivo local como -v ./my.cnf:/etc/mysql/conf.d/custom.cnf
En el propio MariaDB (para ver cuál usa): SELECT @@datadir; o mysqld --verbose --help | grep -A 1 "Default options"

Estructura del archivo y parámetros clave

El archivo usa grupos de configuración entre corchetes. Los parámetros del motor van bajo [mysqld].

# /etc/mysql/mariadb.conf.d/50-server.cnf

[mysqld]
# ── RED ──────────────────────────────────────────────────
bind-address            = 0.0.0.0    # Escuchar en todas las IPs (necesario para acceso remoto)
port                    = 3306

# ── CONEXIONES ───────────────────────────────────────────
max_connections         = 150        # Máximo de conexiones simultáneas
wait_timeout            = 600        # Segundos de espera en conexión inactiva (no interactiva)
interactive_timeout     = 3600       # Ídem para clientes interactivos (DBeaver, terminal...)

# ── RENDIMIENTO ──────────────────────────────────────────
innodb_buffer_pool_size = 512M       # La caché principal de InnoDB. Regla general: 70% de la RAM
innodb_log_file_size    = 128M       # Tamaño de los redo logs: mayor = menos flushes, más rendimiento
query_cache_size        = 0          # En MariaDB 10.5+ la caché de queries está deprecated, mejor en 0
tmp_table_size          = 64M        # Tamaño máximo de tablas temporales en memoria
max_heap_table_size     = 64M        # Debe coincidir con tmp_table_size

# ── LOGS ─────────────────────────────────────────────────
log_error               = /var/log/mysql/error.log
slow_query_log          = 1
slow_query_log_file     = /var/log/mysql/mariadb-slow.log
long_query_time         = 2          # Registrar consultas que tarden más de 2 segundos
log_queries_not_using_indexes = 1    # Registrar también consultas sin índice aunque sean rápidas

Flujo de trabajo: cambiar un parámetro y verificarlo

# Editar el archivo (necesita sudo)
sudo nano /etc/mysql/mariadb.conf.d/50-server.cnf

# Aplicar los cambios reiniciando el servicio
sudo systemctl restart mariadb

# Verificar que arrancó bien (sin errores)
sudo systemctl status mariadb

-- Verificar el valor actual de cualquier variable
SHOW VARIABLES LIKE 'max_connections';
SHOW VARIABLES LIKE 'slow_query_log%';
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';

-- Ver TODAS las variables que coinciden con un patrón
SHOW VARIABLES LIKE '%timeout%';

-- Ver el estado en tiempo real (variables dinámicas)
SHOW STATUS LIKE 'Threads_connected';   -- conexiones activas ahora mismo
SHOW STATUS LIKE 'Slow_queries';        -- número de consultas lentas desde que arrancó

Algunos parámetros son dinámicos: se pueden cambiar en caliente con SET GLOBAL sin necesidad de reiniciar. Esto es crítico en producción (¡no puedes apagar la base de datos!).

-- Activar el slow query log en caliente
SET GLOBAL slow_query_log = 1;
SET GLOBAL long_query_time = 1;

-- Cambiar max_connections sin reiniciar
SET GLOBAL max_connections = 200;

-- ⚠️ IMPORTANTE: Los cambios con SET GLOBAL NO son permanentes.
-- Al reiniciar el servidor, MariaDB leerá el my.cnf de nuevo.
-- Debes editar TAMBIÉN el my.cnf para que el cambio persista.
La importancia de documentar los cambios de configuración

En un entorno de producción, tocar el my.cnf es una intervención crítica. Si algo sale mal después de un cambio, alguien tiene que poder responder estas preguntas en cuestión de minutos:

  • ¿Qué cambiaste exactamente? — No «ajusté la memoria», sino «cambié innodb_buffer_pool_size de 256M a 512M».
  • ¿Por qué lo cambiaste? — Qué problema o métrica te llevó a hacerlo.
  • ¿Quién lo hizo y cuándo? — Con fecha y hora exactas, no «la semana pasada».
  • ¿Qué impacto tuvo? — ¿Mejoró la latencia? ¿El servidor aguantó más conexiones? ¿O empeoró algo?

La herramienta más sencilla para esto en un proyecto técnico es un fichero CHANGELOG.md en el repositorio, con una entrada por cada cambio:

## 2025-03-15 — bernat@server-prod-01

**Cambio:** innodb_buffer_pool_size: 256M → 512M
**Motivo:** El slow query log mostraba 300+ consultas lentas/hora.
            SHOW STATUS indicaba ratio de cache hit del 72% (ideal >95%).
**Resultado:** Cache hit subió al 94%. Consultas lentas/hora bajaron a 12.
**Reversión:** Volver a 256M si el servidor baja de 1GB de RAM libre.

En empresas más grandes, estos registros se hacen en sistemas de tickets (Jira, Redmine) o en pipelines de IaC (Infrastructure as Code) como Ansible o Terraform, donde el propio historial de git sirve como registro de auditoría.
