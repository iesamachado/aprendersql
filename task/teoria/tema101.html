1.1 ¿Cómo guardamos la información en el ordenador?

En informática, tenemos dos tipos de memoria: la volátil y la persistente.

Memoria Volátil (RAM)

Es de más rápido acceso, pero se pierde al apagar el equipo.

Memoria Persistente

Es la que guardamos en el disco duro, pendrive, CD...

Ficheros

Para guardar la información en disco, usamos los ficheros. Son estructuras de información creadas por los Sistemas Operativos para poder almacenar datos. Según el tipo de fichero, guardaremos la información de una manera u otra.

Por Contenido
  • Texto: Organizado con caracteres alfanuméricos. (Bloc de notas)
  • Binario: Datos complejos que requieren software (imagen, video, etc.)
Por Organización
  • Secuenciales: Recorrer todos los anteriores.
  • Relativos: Posicionados a X posiciones, permite "saltar".
  • Indexados: Tienen índice para saltar a cualquier dato.
Por Utilidad
  • Maestro: Info principal de la app.
  • Histórico: Transacciones pasadas no necesarias.
  • Temporal: De uso transitorio.

Ficheros de Texto

  • Configuración: .config, .ini, .inf
  • Código fuente: .java, .cpp, .py, .js
  • Texto plano: .txt
  • Marcado: .xml, .html

Ficheros Binarios

  • Imagen: .jpg, .png
  • Sonido/Video: .wav, .mp3, .mov
  • Comprimidos: .zip, .rar
  • Ejecutables: .exe, .apk

1.2 ¿Qué es una BBDD?

Una base de datos es un conjunto de datos ordenados que están relacionados entre sí y almacenados sistemáticamente para su uso posterior de forma automatizada con un mismo contexto.

Conjunto de Datos

Información sobre objetos o sucesos. Distintos tipos (fechas, números, texto).

Relacionados

Los datos tienen relación entre sí y se define en la estructura.

Almacenados

Su función es guardar de forma persistente la información.

Sistemáticamente

El proceso de creación está parametrizado. Sigue un patrón.

Automatizado

Conjunto de datos digitalizados.

Uso Posterior

Poder consultar y manipular los datos es su gran potencial.

Contexto

Es primordial. Un campo fecha puede ser de pedido, cumpleaños, registro... Sin contexto (nombre de campo o tabla) no podemos interpretar los datos.

1.3 Sistemas Gestores de BBDD (SGBD)

En los años 70, aparece el primer software para gestionar BBDD: Oracle.

Se define un SGBD como un conjunto de herramientas que facilitan la consulta, uso y actualización de una Base de Datos.

Ejemplos: MySQL, MariaDB, PostgreSQL, Oracle, Microsoft SQL Server, MongoDB.

Características de un SGBD:

  • Abstracción: Nos olvida de cómo y dónde se almacenan físicamente los datos.
  • Integridad: Garantiza tipos correctos y recuperación.
  • Seguridad: Autenticación, usuarios y permisos.
  • Metadata: Proporciona estructura y esquema.
  • Transacciones: Garantiza operaciones completas (todo o nada).
  • Monitorización: Estado, consultas, uso de recursos.
  • Concurrencia: N personas a la vez (soluciona problemas de lectura/escritura).
  • Independencia: Separa el software del acceso a datos.
  • Conectividad: Conexión externa, distribución y replicación.

Un poco de historia

  • Desde que el ser humano documenta, almacena datos (Biblioteca Alejandría).
  • 1884: Herman Hollerith, tabulador de tarjetas perforadas.
  • 1963: Primera vez que se usa el concepto de Base de Datos.
  • Años 60: Charles Bachman desarrolla bases de datos en red.
  • Años 70: Edgar Frank Codd desarrolla el modelo relacional.
  • Larry Ellison (basado en Codd) crea Oracle.
  • Años 80: Creación de SQL (Structured Query Language).

Tipos de SGBD

Software Libre

Libertades: usar, estudiar, distribuir y mejorar.

  • MySQL: Muy popular, comprado por Oracle.
  • MariaDB: Fork comunitario de MySQL.
  • PostgreSQL: Robusto, ideal BBDD grandes, alta concurrencia.
Software Propietario

Dos opciones predominan:

  • Oracle: El original.
  • SQL Server: Microsoft.

Comparten casi todo SQL, con algunas diferencias.

¿Y MongoDB? (NoSQL)

Existen BBDD No-SQL donde se rompe la estructura relacional. SQL y NoSQL no son incompatibles, se complementan.

1.4 ¿Qué es SQL?

Structured Query Language: Lenguaje de consulta estructurado para comunicarnos con la BBDD. Tiene 4 sublenguajes:

DDL

Data Definition Language

Definir BBDD (Crear, borrar, modificar tablas).

CREATE, DROP, ALTER

DML

Data Manipulation Language

Trabajar con los datos (consultar, insertar, modificar, borrar).

SELECT, INSERT, UPDATE, DELETE

DCL

Data Control Language

Control de accesos y permisos a la BBDD.

GRANT, REVOKE

TCL

Transaction Control Language

Transacciones ("guardar partida", bloque seguro).

BEGIN TRAN, ROLLBACK TRAN

1.5 BBDD Distribuidas

Originalmente centralizadas, hoy es habitual tenerlas distribuidas en la red.

  • Centralizado: Simplifica el acceso/escritura, pero hay riesgo ante caída.
  • Distribuido: Resistente a caídas, pero dificulta la escritura. Formas: Replicación, Centralizada, Particionada, Híbrida.
Ventajas
  • Autonomía local
  • Mayor disponibilidad
  • Escalabilidad
  • Expansión territorial
  • Más resistente a fallos
Desventajas
  • Dificultad para garantizar seguridad
  • Errores de red
  • Mayor complejidad
  • Problemas de privacidad
  • Modelos más nuevos = más vulnerables
