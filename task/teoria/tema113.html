1. ¿Por qué asegurar los datos?

Una base de datos en producción puede perderse por múltiples causas: un fallo de hardware, un error humano (un DELETE sin WHERE...), un ataque ransomware o simplemente una migración fallida. Sin una política de copias de seguridad, la empresa puede perder datos irreemplazables.

Error Humano
Un DELETE FROM pedidos sin WHERE, un DROP TABLE accidental... Es la causa más frecuente de pérdida de datos.
Fallo de Hardware
Los discos duros tienen una vida útil limitada. Un RAID no es un sustituto de un backup: protege contra fallos de disco, pero no contra borrados lógicos.
Ataque / Ransomware
Un backup offline o en una ubicación separada es la única defensa efectiva contra el cifrado malicioso de datos.
Regla del 3-2-1: Mantén 3 copias de los datos, en 2 soportes diferentes, con 1 de ellas en una ubicación externa (nube, cinta, disco externo fuera de las instalaciones).

2. Tipos de Copia de Seguridad

Existen distintas estrategias de backup según la frecuencia, el volumen y el tiempo de recuperación que necesitemos:

Tipo¿Qué guarda?VentajaDesventajaEjemplo de uso
Completo Toda la base de datos íntegra. Restauración simple y rápida. Ocupa más espacio y tarda más. Cada fin de semana.
Incremental Solo los cambios desde el último backup (completo o incremental). Muy rápido. Ocupa poco. Para restaurar necesitas el completo + todos los incrementales en orden. Cada noche de lunes a viernes.
Diferencial Los cambios desde el último backup completo. Restauración más simple que incremental (solo 2 ficheros). Crece con el tiempo hasta el próximo completo. Cada noche + completo semanal.
RTO y RPO: los dos parámetros clave

RTO (Recovery Time Objective): ¿Cuánto tiempo máximo puede estar el sistema caído? (ej. 4 horas)

RPO (Recovery Point Objective): ¿Cuántos datos podemos permitirnos perder? (ej. datos de las últimas 24 horas)

Backup lógico vs. físico

Lógico: Exporta sentencias SQL (CREATE TABLE, INSERT...). Es legible y portable entre distintos SGBD. Es lo que hace mysqldump.

Físico: Copia binaria de los ficheros del motor. Es más rápido para BD grandes pero menos portable. Lo hace mariabackup.

3. Backup con mysqldump

mysqldump es la herramienta de línea de comandos estándar para hacer backups lógicos en MariaDB/MySQL. Genera un fichero .sql con todas las sentencias necesarias para recrear la base de datos desde cero.

Sintaxis general
mysqldump [opciones] -u USUARIO -p NOMBRE_BD > fichero_backup.sql

El símbolo > redirige la salida estándar al fichero. Se ejecuta desde la terminal del servidor o del contenedor Docker.

Casos de uso más habituales

# Exporta toda la BBDD "arepazo" al fichero backup_arepazo.sql
mysqldump -u root -p arepazo > backup_arepazo.sql

# Con fecha en el nombre (buena práctica):
mysqldump -u root -p arepazo > backup_arepazo_$(date +%Y%m%d).sql

El fichero resultante contendrá los CREATE TABLE y los INSERT INTO de todos los datos.

# Solo la tabla "Pedidos" de la BD "arepazo"
mysqldump -u root -p arepazo Pedidos > backup_pedidos.sql

Útil cuando solo necesitas recuperar o mover una tabla específica.

OpciónEfecto
--no-dataExporta solo la estructura (DDL), sin datos.
--no-create-infoExporta solo los datos (INSERT), sin DDL.
--all-databasesHace backup de todas las BD del servidor.
--single-transactionBackup consistente sin bloquear tablas (InnoDB). Recomendado en producción.
--routinesIncluye procedimientos almacenados y funciones.
--triggersIncluye los triggers (activado por defecto).
 
# Backup completo, consistente, con rutinas, comprimido con gzip:
mysqldump -u root -p --single-transaction --routines arepazo | gzip > backup_arepazo.sql.gz

# Ejecutar mysqldump DENTRO del contenedor y guardar en el HOST:
docker exec NOMBRE_CONTENEDOR mysqldump -u root -pCONTRASEÑA arepazo > backup_arepazo.sql

# Ejemplo real (sustituir nombre y contraseña):
docker exec mariadb_clase mysqldump -u root -p1234 arepazo > backup_arepazo.sql

Atención: la contraseña va pegada a -p sin espacio cuando se automatiza, para evitar la pregunta interactiva.

Herramienta gráfica: DBeaver — Exportar como SQL dump
  1. En el panel izquierdo (Database Navigator), haz clic derecho sobre la base de datos que quieres exportar.
  2. Selecciona Tools → Dump database.
  3. Elige las tablas a incluir y las opciones (estructura, datos, rutinas...).
  4. Indica la ruta del fichero de salida y haz clic en Start.

DBeaver llama internamente a mysqldump. Es la opción más cómoda si no te sientes seguro con la terminal.

4. Restauración de una Copia de Seguridad

Restaurar significa aplicar el fichero .sql sobre un servidor MariaDB. El proceso crea las tablas y vuelve a insertar todos los registros.

¡Cuidado! Si la BD de destino ya tiene datos, la restauración normalmente los sobreescribirá. Asegúrate de que sabes lo que haces antes de restaurar en producción.
Desde la terminal
# 1. Crear la BD si no existe:
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS arepazo;"

# 2. Restaurar el backup:
mysql -u root -p arepazo < backup_arepazo.sql

El símbolo < redirige el fichero como entrada estándar del cliente mysql.

Desde un contenedor Docker
# Restaurar directamente con redirección:
docker exec -i mariadb_clase mysql -u root -p1234 arepazo < backup_arepazo.sql
Restaurar con DBeaver
  1. Clic derecho sobre la base de datos de destino → Tools → Restore database.
  2. Selecciona el fichero .sql del backup.
  3. Haz clic en Start y espera a que termine.

5. Importación de Datos desde CSV

Es muy habitual recibir datos desde hojas de cálculo u otras aplicaciones en formato CSV (Comma-Separated Values). MariaDB ofrece dos formas principales de importar CSV:

LOAD DATA INFILE (SQL)
LOAD DATA INFILE '/var/lib/mysql-files/clientes.csv'
INTO TABLE Clientes
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS
(nombre, apellido, email, telefono);

Requiere el privilegio FILE y que el fichero esté en el directorio permitido (secure_file_priv).

DBeaver — Importar CSV (recomendado en clase)
  1. Clic derecho sobre la tabla de destino.
  2. Selecciona Import Data.
  3. Elige el formato CSV.
  4. Selecciona el fichero, confirma el separador y el encoding.
  5. Mapea las columnas del CSV con las columnas de la tabla.
  6. Haz clic en Proceed.
Ejemplo completo: importar un CSV de equipos NBA

Supón que tienes el fichero equipos.csv con este contenido:

nombre,ciudad,conferencia,fundacion
Los Angeles Lakers,Los Angeles,Oeste,1946
Boston Celtics,Boston,Este,1946
CREATE TABLE IF NOT EXISTS equipos_import (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  ciudad VARCHAR(80),
  conferencia VARCHAR(10),
  fundacion YEAR
);

LOAD DATA INFILE '/var/lib/mysql-files/equipos.csv'
INTO TABLE equipos_import
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS
(nombre, ciudad, conferencia, fundacion);

6. Exportación de Datos

Además de exportar como SQL dump, podemos exportar los resultados de una consulta a distintos formatos (CSV, JSON, Excel...) para compartirlos con otras aplicaciones.

SELECT ... INTO OUTFILE (SQL)
SELECT id, nombre, email
FROM Clientes
WHERE activo = TRUE
INTO OUTFILE '/var/lib/mysql-files/clientes_activos.csv'
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n';
DBeaver — Exportar resultados
  1. Ejecuta tu consulta SELECT en DBeaver.
  2. En el panel de resultados, clic en el botón Export results.
  3. Selecciona el formato: CSV, JSON, XLS, HTML...
  4. Configura el separador y encoding.
  5. Elige la ruta de destino y haz clic en Proceed.

7. Ficheros de Log y Recuperación de Errores

MariaDB mantiene varios ficheros de registro que son esenciales para diagnosticar problemas y, en algunos casos, recuperar datos.

Error Log

Registra los errores del motor, advertencias y mensajes de inicio/parada.

docker exec mariadb_clase tail -f /var/log/mysql/error.log

Variable: log_error

General Query Log

Registra todas las consultas ejecutadas. Útil para depuración, pero muy pesado en producción.

SET GLOBAL general_log = 'ON';
SET GLOBAL general_log_file = '/tmp/mysql_general.log';

No dejes el general log activo en producción.

Binary Log (binlog)

Registra todos los cambios de datos. Permite replicación y recuperación punto en el tiempo.

mysql -u root -p -e "SHOW BINARY LOGS;"
mysqlbinlog /var/lib/mysql/mariadb-bin.000001
Slow Query Log

Registra las consultas que tardan más de un umbral definido. Imprescindible para detectar cuellos de botella.

SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 2;  -- umbral en segundos

Errores más comunes y cómo interpretarlos

CódigoMensajeCausaSolución
1062 Duplicate entry '...' for key 'PRIMARY' ID ya existe en la tabla. Usa INSERT IGNORE o ON DUPLICATE KEY UPDATE.
1451 Cannot delete or update a parent row (FK) El registro tiene hijos en otra tabla. Borra primero los hijos, o usa ON DELETE CASCADE en la FK.
1452 Cannot add or update a child row (FK) La FK no existe en la tabla padre. Inserta primero el registro padre.
2002 Can't connect to local MySQL server El servicio MariaDB no está arrancado. docker start mariadb_clase
1045 Access denied for user '...' Usuario/contraseña incorrectos o sin permisos. Revisa credenciales. Admin puede usar GRANT.

8. Transferencia de Datos entre SGBD

En entornos reales es frecuente necesitar migrar datos entre distintos motores: de MySQL a PostgreSQL, de Access a MariaDB, de SQL Server a MariaDB, etc.

Vía SQL Dump

Exportas de origen, adaptas el SQL a la sintaxis del destino y lo importas.

Problema: los dialectos SQL son diferentes.

Vía CSV

Exportas a CSV desde el origen (agnóstico del SGBD) e importas en el destino.

La más universal. Funciona entre cualquier par de SGBD.

Herramientas ETL / DBeaver

DBeaver permite transferir datos directamente entre dos conexiones activas sin exportar a fichero intermedio.

ETL profesionales: Pentaho, Apache NiFi.

Transferencia con DBeaver (paso a paso)
  1. Crea dos conexiones en DBeaver: una para el SGBD origen y otra para el destino.
  2. Abre la conexión de origen, navega hasta la tabla que quieres copiar.
  3. Clic derecho → Export Data.
  4. En «Target container», selecciona la conexión de destino y la BD/tabla de destino.
  5. Mapea las columnas (DBeaver lo hace automáticamente si los nombres coinciden).
  6. Haz clic en Proceed.

Ejercicios Prácticos del RA6

Enunciado: Realiza un backup completo de la base de datos arepazo usando mysqldump. El fichero de salida debe llamarse backup_arepazo_FECHAHOY.sql. Adapta el comando a tu entorno (Docker o instalación directa).

Ver solución 
# Sin Docker:
mysqldump -u root -p arepazo > backup_arepazo_$(date +%Y%m%d).sql

# Con Docker:
docker exec mariadb_clase mysqldump -u root -p1234 arepazo > backup_arepazo_$(date +%Y%m%d).sql

Enunciado: Genera un fichero SQL que contenga solo la estructura (CREATE TABLE) de la base de datos nba, sin ningún dato.

Ver solución 
mysqldump -u root -p --no-data nba > estructura_nba.sql

Enunciado: A partir del backup del ejercicio 1, crea una nueva BD llamada arepazo_restaurada y restaura el backup en ella. Comprueba con SHOW TABLES que todo está correcto.

Ver solución 
mysql -u root -p -e "CREATE DATABASE arepazo_restaurada;"
mysql -u root -p arepazo_restaurada < backup_arepazo_FECHAHOY.sql
mysql -u root -p -e "USE arepazo_restaurada; SHOW TABLES;"

Enunciado: Exporta el nombre, ciudad y conferencia de todos los equipos de la BD nba a un fichero CSV usando SELECT INTO OUTFILE. Si el servidor no permite OUTFILE, usa DBeaver para exportar el resultado de la misma consulta.

Ver solución (SQL) 
SELECT nombre, ciudad, conferencia
FROM nba.equipos
INTO OUTFILE '/var/lib/mysql-files/equipos_nba.csv'
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n';

Enunciado: Para cada mensaje de error, indica la causa y la solución:

  1. ERROR 1062 (23000): Duplicate entry '5' for key 'PRIMARY'
  2. ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`arepazo`.`PedidosLinea`, CONSTRAINT `fk_pedido`...)
  3. ERROR 1045 (28000): Access denied for user 'alumno'@'localhost' (using password: YES)
Ver soluciones

1. Ya existe un registro con id=5. Solución: cambia el id o usa INSERT IGNORE / ON DUPLICATE KEY UPDATE.

2. Intentas borrar un Pedido que tiene líneas asociadas. Solución: borra primero las líneas (DELETE FROM PedidosLinea WHERE pedido_id = X) y luego el pedido.

3. Contraseña incorrecta o sin permisos. Solución: verifica credenciales. Si eres admin: GRANT ALL ON arepazo.* TO 'alumno'@'localhost';

Resumen del Tema 6 — Lo esencial
  • Un backup es la única protección real contra pérdida de datos.
  • Regla 3-2-1: 3 copias, 2 soportes, 1 ubicación externa.
  • mysqldump genera backups lógicos (SQL) portables y legibles.
  • La restauración usa el cliente mysql con redirección <.
  • LOAD DATA INFILE / SELECT INTO OUTFILE para CSV.
  • DBeaver simplifica todas estas operaciones con interfaz gráfica.
  • Los logs (error, binlog, slow query) son fundamentales para el diagnóstico.
  • La transferencia entre SGBD se puede hacer vía CSV o con DBeaver directamente.
