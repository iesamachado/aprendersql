1. Triggers (Disparadores)

Los triggers o disparadores son procedimientos que se ejecutan de forma automática cuando pasa algo en la base de datos (eventos INSERT, UPDATE o DELETE).

¿Para qué sirven?

  • Registrar, auditar y monitorear los procesos de cambio.
  • Validar valores aprobando o negando acciones realizadas por sentencias SQL.
  • Preservar la consistencia y claridad de los valores (ej. recalcular el total de un pedido al añadir una línea).
Ventajas
  • Ofrecen chequeos de seguridad en valores de las tablas.
  • Fuerzan restricciones dinámicas de integridad de datos e integridad referencial.
  • Aseguran que las operaciones relacionadas se realicen juntas de forma implícita.
Desventajas
  • Se tiene que programar anticipadamente lo que tiene que realizar el trigger.
  • Aunque es un procedimiento, no se puede invocar directamente.

Sintaxis de Creación

CREATE TRIGGER nombre_trigger
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON nombre_tabla
FOR EACH ROW
BEGIN
    -- Acciones SQL a ejecutar
END;
BEFORE o AFTER:
  • BEFORE: Si queremos que se ejecute ANTES del evento que ha disparado el trigger.
  • AFTER: Si queremos que se ejecute DESPUÉS del evento.

Tablas NEW y OLD

Nos servirán en nuestros triggers para recuperar los valores que se han modificado y han disparado nuestro trigger.

Tabla NEW

Disponible en triggers de INSERT y UPDATE. Contiene los nuevos valores insertados o actualizados.

Tabla OLD

Disponible en triggers de DELETE y UPDATE. Contiene los valores antiguos o borrados.

2. Cursores (Iteración)

Los cursores permiten iterar a través de un conjunto de resultados (filas de una consulta SELECT) dentro de un procedimiento almacenado o trigger, procesando una fila a la vez.

Pasos para usar un Cursor

  1. Declaración: DECLARE nombre_cursor CURSOR FOR consulta_select;
  2. Apertura: OPEN nombre_cursor; (Ejecuta la consulta)
  3. Lectura (Fetch): FETCH nombre_cursor INTO variable1, variable2; (Avanza a la siguiente fila)
  4. Cierre: CLOSE nombre_cursor; (Libera los recursos)

Ejemplo de Uso

DELIMITER //
CREATE PROCEDURE procesar_empleados()
BEGIN
    DECLARE done INT DEFAULT FALSE;
    DECLARE var_nombre VARCHAR(100);
    
    -- 1. Declarar cursor
    DECLARE cursor_empleados CURSOR FOR SELECT nombre FROM empleados;
    
    -- Manejador de fin de cursor (ver sección de excepciones)
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;

    -- 2. Abrir cursor
    OPEN cursor_empleados;

    read_loop: LOOP
        -- 3. Leer fila
        FETCH cursor_empleados INTO var_nombre;
        
        IF done THEN
            LEAVE read_loop;
        END IF;
        
        -- Acciones con var_nombre...
    END LOOP;

    -- 4. Cerrar cursor
    CLOSE cursor_empleados;
END //
DELIMITER ;

3. Excepciones (Manejo de Errores)

En MariaDB, el manejo de errores y advertencias en bloques de código se realiza utilizando HANDLERS. Nos permiten definir qué acción tomar cuando ocurre un estado SQL específico, error o si no se encuentran más filas en un cursor.

Sintaxis de Handlers

DECLARE {CONTINUE | EXIT} HANDLER FOR {condición_error} 
BEGIN
    -- Código a ejecutar cuando ocurra la condición
END;
Tipos de Handler
  • CONTINUE
    Ejecuta el bloque del handler y luego continúa con la siguiente instrucción después de la que causó el error.
  • EXIT
    Ejecuta el bloque del handler y luego termina la ejecución del bloque BEGIN...END actual.
Condiciones de Error Comunes
  • SQLEXCEPTION: Cualquier error (estado SQL distinto de 00000, 01000 y 02000).
  • SQLWARNING: Advertencias (estado SQL comienza con 01).
  • NOT FOUND: Usado típicamente en cursores cuando FETCH no encuentra más filas.
  • Código de error SQL: Por ejemplo, 1062 (Entrada duplicada).

4. Eventos Programados

Los eventos (Events) son tareas planificadas que el servidor ejecuta de forma automática en un momento específico o en intervalos regulares (similar a los cron jobs de Linux).

Importante: Para que los eventos funcionen, el planificador de eventos debe estar activo en el servidor: SET GLOBAL event_scheduler = ON;

Sintaxis Básica

CREATE EVENT nombre_evento
ON SCHEDULE {AT timestamp | EVERY intervalo}
[STARTS timestamp] [ENDS timestamp]
DO
BEGIN
    -- Sentencias SQL
END;
Evento Único (AT)

Se ejecuta una sola vez en el momento especificado.

CREATE EVENT evento_unico
ON SCHEDULE AT CURRENT_TIMESTAMP + INTERVAL 1 HOUR
DO
  UPDATE ofertas SET activa = FALSE;
Evento Recurrente (EVERY)

Se repite periódicamente.

CREATE EVENT limpiar_logs
ON SCHEDULE EVERY 1 WEEK
DO
  DELETE FROM logs WHERE fecha < NOW() - INTERVAL 1 MONTH;
